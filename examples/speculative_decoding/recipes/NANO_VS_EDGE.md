# Cosmos3 Nano vs Cosmos3 Edge — DFlash recipe diffs

This is the review surface for an Edge DFlash recipe. Do not treat a JSON diff of `train_dflash_cosmos3_nano.ipynb` as the spec: the Nano notebook hard-codes Qwen3-VL tokenizer IDs and draft shapes. Pointing `MODEL_PATH` at [nvidia/Cosmos3-Edge](https://huggingface.co/nvidia/Cosmos3-Edge) is not enough.

The Nano runbook remains `train_dflash_cosmos3_nano.ipynb` (configure → build data → train → export). The Edge sibling is `train_dflash_cosmos3_edge.ipynb`, generated by `derive_cosmos3_edge_recipe.py`. This file is the contract for what must change.

**Target checkpoint:** public [`nvidia/Cosmos3-Edge`](https://huggingface.co/nvidia/Cosmos3-Edge) (`main` at `a9d944e2c6a1bf9f48b92ad16348e70c5f1836ba`, 2026-08-26). The model card’s **vLLM** section deploys this same repo as the Cosmos3-Edge **reasoner**. Do not switch to NGC unless that revision is shown to differ. The snapshot also contains diffusion `transformer/` + `vae/` (Omni); DFlash uses the AR/VLM reasoner path, not Diffusers.

Sources for Nano: `cosmos3-nano-reasoner` `config.json` (`Qwen3VLForConditionalGeneration`) and the production overrides in `train_dflash_cosmos3_nano.ipynb`. Tokenizer/config below were loaded from the Edge snapshot (`AutoTokenizer`, `trust_remote_code=True`).

Training needs a transformers build that registers `cosmos3_edge` (5.12 cannot load the class). The generated Edge recipe pins Transformers `5.18.0.dev0` at commit `df04b012229d50d2b6dfba32c61c3057c3a40ea1`. Do not upgrade a Nano train environment in place, and do not put the training overlay on vLLM’s `PYTHONPATH`.

## Diffs vs Nano

These Nano notebook values must not be copied onto Edge. Swapping only `MODEL_PATH` is not a recipe.

| Item | Nano (locked in the notebook) | Edge (public checkpoint) | Action |
| --- | --- | --- | --- |
| Target class | `Qwen3VLForConditionalGeneration` / `qwen3_vl` | `Cosmos3EdgeForConditionalGeneration` / `cosmos3_edge` | Load Edge with the matching processor; expect `trust_remote_code` |
| Family | Qwen3-VL text tower | Mixture-of-Transformers (card); text tower `cosmos3_edge_text` | Use the **reasoner / AR text+vision** weights, not a policy or generator-only blob |
| Size (card) | ~16B | ~4B | Draft `hidden_size` follows the **text** tower (`2048`), not Nano’s 4096 |
| Tokenizer / vocab | Qwen3, `vocab_size` 151936 | Nemotron-style specials, `vocab_size` 131072 | Rebuild JSONL with the Edge tokenizer |
| `dflash_mask_token_id` | `151669` | Out of range for 131072 | Use **`100`**. Do not reuse 151669 |
| Draft heads | `num_attention_heads=32`, `num_key_value_heads=8`, `head_dim=128` | Text tower: **16 / 8 / 128**, `hidden_size=2048` | 32 heads × `head_dim=128` does not match `hidden_size=2048` |
| Draft MLP / RoPE | `intermediate_size=12288`, `rms_norm_eps=1e-06`, `rope_theta=5000000`, `max_position_embeddings=262144` | Text: `9216`, `1e-05`, `1e8`, `131072` | Override from Edge `text_config` |
| Activation | Text `silu`; DFlash draft is Qwen3 MLP | Text `relu2` | Draft stays Qwen3-shaped (`silu` in `dflash.md`). `relu2` is not a drop-in draft flag |
| Vision token IDs | `image=151655`, `video=151656`, `vision_start=151652`, `vision_end=151653` | `image=19`, `video=18`, `vision_start=20`, `vision_end=21` | Hard-coded Qwen VL ids will break data / chat templates |
| EOS | `151645` | `11` (`<\|im_end\|>`) | Completions and stop criteria must use Edge ids |
| Thinking prefill | Generation prompt is `<\|im_start\|>assistant\n`; the model emits `<think>` itself | Generation prompt is `<\|im_start\|>assistant\n<think>\n` | Edge completions come back **without** the opening tag. See [Thinking tags](#thinking-tags-in-synthetic-completions) |
| M-RoPE | Qwen `rope_scaling.mrope_section = [24, 20, 20]` | `rope_parameters.mrope_section = [24, 20, 20]` | **Do not inherit M-RoPE onto the draft**; vLLM speculative decoding still wants standard RoPE on the draft (`doc/dflash.md`) |

## Safe to reuse from Nano (until measured otherwise)

Recipe *process* defaults, not architecture facts:

- Four-step runbook shape
- DFlash block size `8`, `num_anchors=128`, loss `decay` / `decay_factor=4`
- Draft **depth** `num_hidden_layers=5` (independent of the 28-layer Edge text tower; KV injection still needs `hidden_size` alignment)
- `training_seq_len=16384` (must stay divisible by block size)
- 8 GPU, per-device batch 1, grad accum 2 → **global batch 16** (1-GPU equivalent: accum 16)
- `num_train_epochs=25`, `logging_steps=10`, `save_steps=1000`, `answer_only_loss=true`, `report_to=none`; the notebook sets no `max_steps` and no `learning_rate`, so `dflash.yaml` supplies **LR `6.0e-4`**, `warmup_steps=100`, `lr_scheduler_type=linear`
- Image/video token budgets from the notebook’s training cell: `VLM_MIN_PIXELS=50176`, `VLM_MAX_PIXELS=802816`, `VLM_VIDEO_MIN_PIXELS=100352`, `VLM_VIDEO_MAX_PIXELS=2097152`. Do not invent these; the target’s completions and the draft’s inputs have to come from the same resolution
- Export via `examples/speculative_decoding/scripts/export_hf_checkpoint.py` — never serve a raw Trainer `checkpoint-*`
- vLLM `method=dflash`, `num_speculative_tokens=7`

## Data

Nano production JSONL is tokenized / templated for Qwen3-VL. Edge still needs:

1. Edge processor + chat template for PAI / VQA / text sources
2. Completions from the **Edge** target, not Nano
3. A fresh merge (`merge_dflash_datasets.py`); media paths can follow the same absolute-path convention (`data.vlm_img_dir=/`)

The Edge notebook keeps the Nano source structure:

- the same deterministic five-shard PAI prompt sample, with Edge assistants
- the same deterministic 20,000-prompt VQA sample, with Edge assistants
- optional curated text (`PLAIN_TEXT_INPUT`) if those assistants are acceptable for the run
- multilingual prompt shards, with eight Edge temperature variants

Do not replace shard semantics with rank/modulo sampling or feed prior Nano output rows back as prompts. Site-specific output directories and any first-run shard cap belong in a private ops checkout, not in this contract.

### Generation parameters (do not invent these)

Row counts are not prompt counts. The notebook runs **`NUM_TEMPERATURES=8`** and the workers derive temperature from the index, so every prompt is generated eight times at `0.0 … 0.7`.

| Knob | Notebook / worker value | Source |
| --- | --- | --- |
| Temperatures | **8**, `0.0` through `0.7`, one pass each | notebook `NUM_TEMPERATURES=8`; `worker.sh` / `worker_multimodal.sh` `printf "0.%d"` |
| `max_tokens` (text) | **4096** | `distributed_generate/worker.sh` |
| `max_tokens` (PAI / VQA) | **6144** | `distributed_generate/worker_multimodal.sh` |
| `top_p` | not sent → server default `1.0` | `scripts/server_generate.py` sends only `max_tokens` and `temperature` |
| Video frames | **16** | notebook → `run_multimodal_synthetic_generation.sh`; the downstream `32` defaults are bypassed |
| Video `fps` in the prompt row | `4` | `prepare_multimodal_synthetic_shards.py` |
| Backend | Nano: text `vllm`, MM `sglang`; Edge: `vllm` for both | See below. Do not copy Nano’s MM `sglang` launch onto Edge |
| Empty completions | written without a `conversations` field (`--log_empty_conversations`), so the merge drops them | `server_generate.py` |
| Truncated completions | kept, flagged `truncated: true` on `finish_reason == "length"`; `merge_dflash_datasets.py` only drops `generation_error` | `server_generate.py`, `merge_dflash_datasets.py` |

Generation-time image and video pixel budgets must match the training cell’s `VLM_*_PIXELS` values listed above.

Nano MM sglang is **Qwen3-VL chat**: `sglang.launch_server` plus `server_generate_vlm_sglang.py` produce assistant text for PAI/VQA. That path is not “any Cosmos checkpoint on SGLang.” Public SGLang support for `nvidia/Cosmos3-Edge` is the **diffusion generator** (T2I/T2V, `/v1/images`, `/v1/videos`), which is the Omni stack this recipe explicitly does not train on. DFlash needs the **AR/VLM reasoner** (`Cosmos3EdgeForConditionalGeneration`). vLLM 0.27 already implements that class; Edge generation and later `method=dflash` serving were validated there, with `edge_compat` for transformers 5.15 mismatches and the aux remap. Using Nano’s sglang worker on Edge would either fail to load the reasoner or walk into the generator API. The temperatures, `max_tokens`, and frame count stay the Nano values; only the serving engine changes.

The vLLM aux-layer remap below is a **serve-time AL** issue. Frozen-target synthetic generation does not use DFlash. It still uses vLLM because that is the engine that can run the Edge reasoner.

### Thinking tags in synthetic completions

Edge’s `chat_template.jinja` **prefills the opening `<think>`** in the generation prompt:

```jinja
{%- if add_generation_prompt %}
    {%- if enable_thinking %}
        {{- '<|im_start|>assistant\n<think>\n' }}
```

So a completion starts *inside* the thinking block: the returned text has a `</think>` but no `<think>`. Nano is the opposite — its `chat_template.json` contains no `<think>` at all, the generation prompt is just `<|im_start|>assistant\n`, and Qwen3-VL emits `<think>` as its own first tokens.

The generation scripts store `choice.message.content` verbatim (`scripts/server_generate.py`, `distributed_generate/server_generate_vlm_sglang.py`). Nano never needed a fix-up.

The Edge notebook generation cells therefore set `ASSISTANT_PREFIX=$'<think>\n'`. When that env is set, `worker.sh` / `worker_multimodal.sh` pass `--assistant_prefix` so on-disk assistants match Nano’s `<think>` … `</think>` shape.

This is not cosmetic. A training template that treats a missing `<think>` as “no reasoning” will inject an empty block and leave the real `</think>` dangling mid-answer.

Edge never emits that shape at serve time, so the draft would be fit to a distribution that does not occur in deployment. **Prepend `<think>\n` to every Edge completion** when building the JSONL, matching Nano’s on-disk shape, or drop the opening-tag branch from the training template — not both.

No custom Edge training template is needed. The ModelOpt VLM collator derives answer-only labels from the official template’s `<|im_start|>assistant\n ... <|im_end|>` boundaries.

Two related checks on any Edge completion set:

- `max_tokens` must clear the target’s thinking length. Use the worker values above (**4096** text, **6144** media); `server_generate.py`’s own argparse default of 2048 is not what the recipe runs.
- Count rows whose assistant text has `</think>` but no `<think>`, and rows with neither, before merging.

## vLLM DFlash on Edge

DFlash is not EAGLE, but vLLM 0.27 serves it on the EAGLE3 plumbing: shared `embed_tokens` / `lm_head`, and **aux hidden states** from selected target layers (`SupportsEagle3`). `Qwen3VLForConditionalGeneration` already implements that interface. `Cosmos3EdgeForConditionalGeneration` does not; serving has to attach the protocol so the runner can call `set_aux_hidden_state_layers`.

Other 0.27 + transformers 5.15 mismatches that blocked engine init (not DFlash-specific):

- `get_image_size` is on `transformers.image_utils`, not `qwen3_vl` video processing
- DFlash proposer reads `image_token_index`; Edge config only has `image_token_id`
- vLLM’s Edge video processor calls `resize()` with `SizeDict(height, width)`; 5.15 `Qwen3VLVideoProcessor.resize` wants `factor` / `temporal_factor`

Do **not** fix these by putting the train-time transformers overlay on vLLM’s `PYTHONPATH` (EngineCore inherits it and breaks). The local shims live in `examples/speculative_decoding/edge_compat`.

### Aux layer mapping (train vs vLLM serve)

vLLM **does** support `method=dflash`. The open issue is a **layer-index mismatch** between how ModelOpt trains the draft and how vLLM 0.27 picks aux hidden states at serve time.

The draft is trained on features from specific **HuggingFace decoder blocks**. At serve time, vLLM must sample the **same physical activations** from `self.layers`. If the mapping is wrong, load and generate still succeed, but acceptance length (AL) drops because the draft sees the wrong input distribution.

#### Training side (ModelOpt + HF)

`build_target_layer_ids(28, 5)` writes HF block indices into the exported draft config, e.g. `[1, 7, 13, 19, 25]` in `dflash_config.target_layer_ids`. During training and AR validation, features are taken from `hidden_states[lid + 1]` — index `0` is the embedding, index `k` is the output after HF decoder block `k - 1` (attn + MLP fused in one block):

```python
# modelopt/torch/speculative/plugins/hf_dflash.py
hid_offset = 1
selected = [base_outputs.hidden_states[lid + hid_offset] for lid in self.target_layer_ids]
target_hidden = torch.cat(selected, dim=-1)
```

These integers are **HF block ids**, not vLLM `self.layers` indices. Do not change them in export to “fix” serving; remap on the vLLM side instead.

#### Serve side (vLLM)

When the engine starts, `gpu_model_runner._get_eagle3_aux_layers_from_config` reads `dflash_config.target_layer_ids` and applies a single conversion for all targets:

```python
# vllm/v1/worker/gpu_model_runner.py
if dflash_config and isinstance(dflash_config, dict):
    # Add 1 to convert DFlash's aux layer id semantics
    layer_ids = [
        i + 1 for i in (dflash_config.get("target_layer_ids") or [])
    ]
```

So `[1, 7, 13, 19, 25]` becomes aux tuple `(2, 8, 14, 20, 26)`. That `+ 1` assumes **one HF decoder layer maps to one vLLM layer**. This holds for **Qwen3-VL (Nano)**.

#### Why Edge breaks the assumption

Cosmos3-Edge’s HF checkpoint has **28** fused text blocks (`text_config.num_hidden_layers: 28`). vLLM’s Edge implementation loads them through Nemotron-H and **splits each HF block into two `self.layers` entries** (attention, then MLP). The runtime stack has **56** layers while training still refers to **28** HF blocks.

| HF `target_layer_ids` | vLLM today (`i + 1`) | Edge remap (`2 * (i + 1)`) |
| --- | --- | --- |
| 1 | 2 | 4 |
| 7 | 8 | 16 |
| 13 | 14 | 28 |
| 19 | 20 | 40 |
| 25 | 26 | 52 |

Keep this remap in the local serve shim (`edge_compat`). Do **not** rewrite `target_layer_ids` in export `config.json` (that would double-convert if vLLM’s `+ 1` still runs). Do not put this shim on Nano eval `PYTHONPATH`. Confirm with a cosine check (HF `hidden_states[lid+1]` vs vLLM aux candidates) before treating AL as validated.

## Remaining (recipe)

1. Cosine-check the aux remap and measure AL on a trained draft.
2. Rebuild JSONL with Edge completions (same PAI/VQA notebook samples; multilingual may be a shard slice for a first run).
3. Train at global batch 16 / `training_seq_len=16384` with Edge draft shapes and mask `100`. Do not reuse a Nano trainer config that hard-codes Qwen heads, mask `151669`, or `trust_remote_code=false`.
4. MTBench / video AL with the Edge aux remap. Upstream PR to `NVIDIA/Model-Optimizer` after the recipe is validated.
